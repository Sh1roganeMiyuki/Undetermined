# 04 呈现规范（L2）

> 本文档是「观测档案」项目四层文档体系中的 **L2**，也是**唯一的跨层翻译表**。
> 它回答一个问题：`01_设定文档.md` 里的那些世界观概念，在玩家眼里**长成什么样子**，以及我们需要浏览器的哪些**真实信号**才能让它长成那个样子。
>
> 上层：`01`（世界观圣经，不面向玩家，不提技术）、`02`（叙事结构与事件序列）
> 下层：`03`（垂直切片开发提示词，实现层）
>
> **硬性引用规则：`03` 的世界观依据只允许引用本文档（策划层事实可引用 `02`），不允许直接引用 `01`。** 任何"从设定文档里抄一个名词到代码里"的行为都视为违规，包括变量命名。

---

## 〇、这一层的职责

**向上**：规定哪些世界观概念允许被呈现、以什么形式呈现（§二 主映射表、§五 不迁移清单）。
**向下**：规定用什么浏览器真实信号实现，禁止自行模拟（§一、§九）。

要堵住的两类事故：世界观名词被直接抄到玩家脸上；实现层自己发明机制（例如把"观测预算"做成五个进度条）。

## 一、翻译三原则

### 1.1 只翻译现象，不翻译名词

玩家永远不应该看到"观测权重""通道预算""定稿"这些词。玩家应该看到的是：一个词条的第三段话，昨天和今天不一样。

世界观名词进入玩家视野的唯一合法路径是**站内文档自身的措辞**——即"观测档案"这个虚构 Wiki 在自己的页面上怎么写自己。除此之外，任何 UI 文案、提示、教学、状态栏都不允许出现 L0 术语。

### 1.2 能用浏览器真实信号实现的，禁止自行模拟

判断标准：**如果浏览器已经知道这件事，就不要自己记账。**

- 反例：用 `setInterval` 每秒扣减"视觉通道预算"。内容与玩家实际行为脱钩，一眼是装的。
- 正例：`IntersectionObserver` 判定某段文字真的进入了视口，只有进入过的那一段才允许变化。

真实信号经得起查看源代码：玩家打开 DevTools 看到的是标准 API 调用，不是我们私有的计数器。

### 1.3 呈现层的含糊是功能，不是缺陷

L2 允许存在"未决项"（见第十节）。把每个世界观概念都翻译干净，等于替玩家完成了思考。

## 二、主映射表：通道 → 真实信号 → 玩家可感现象

`01` 定义七类观测通道。本项目**迁移其中五类**，声学通道与热状态通道不迁移（分别见第五节、4.1）。

| 世界观概念（L0） | 网页真实信号 | 玩家可感现象（L2 规定的呈现形式） | 备注 |
|---|---|---|---|
| 视觉通道 / 有效观测 | `IntersectionObserver`（元素是否真正进入视口）、`document.visibilityState`、`visibilitychange` | 只有玩家真正滚动到、真正停留在视口内超过一定时长的段落，才在后续访问中发生变化。未进入视口的内容变化 = 不允许发生 | 这是"观测才产生作用"的硬实现 |
| 弱观测 / 余光观测 | 后台标签页挂着（`visibilityState === 'hidden'` 但未关闭）、页面驻留时长、无指针活动的时长 | 页面在后台挂着时**不结算**——既不留痕，也不产生任何变化。切片内弱观测是纯粹的"无后果"档 | 曾规定"回到前台的那一次渲染允许出现一次极轻变化"，已撤销：切片内没有任何信号源能区分"走神"与"切走了又切回来"，兑现这句话只能靠随机，而随机会被玩家识破为 bug。不得插入可见的过渡动画，见 6.2 |
| 强观测 / 高权值观测单位 | 精确文本选中（`selectionchange` 选区稳定后结算）、复制（`copy`）——**仅此两项** | 玩家做出这两个动作的条目生成一份**快照**（原样留存当时所见的那一版文本）——此后该条目**不再**漂移，且成为其他条目的对照基准 | 玩家以为自己在核对资料，实际是在给世界定稿。**站内搜索点击进入、跨天回访不属于此项**：前者是导航事件，后者推进轮次，二者都会触发变化而不是终结变化。把它们列为定稿触发条件，等于宣布"玩得越久世界越不动" |
| ~~承载通道 / 触觉观测~~ | —— | **不迁移**：见第五节清单（2026-10-06 对账自本表移出） | 原行声明“已迁移”但实现层从未存在；不做的理由写在 §五 |
| 热状态通道 / **剪枝热** | 无。不采集、不模拟、不产生任何真实负载 | 只作为档案文本里的一个名词存在（"设备发热"是档案自己的说法），玩家设备不发热，页面不显示任何温度读数 | 不迁移，详见 4.1 |
| 语义识别通道 | 站内搜索 query 字符串、query 命中条目数、零结果搜索、同一意图反复改写 query | 搜索结果本身成为异常载体：返回一条不存在于任何索引的条目；返回两条同名同链接、内容互斥的条目 | 对应 `01` EX-06 |
| 时间连续性 | 路由序列 + 时间戳、`lastvisited`、跨自然日回访、会话间隔 | "上次你看到这里"式的错位：不是提示，是内容本身停留在上次的位置，而它周围的一切已经推进 | 不做任何倒计时、进度百分比 |
| 跨通道协调 | `BroadcastChannel`（多标签页心跳租约） | 查阅记录里“同一时间存在其他查阅会话：N”；后台标签页不结算（见弱观测行）。**两标签内容分叉、关一个另一个固化：不实现**，理由见第十节 | 必须用 `BroadcastChannel`，不得用 `sessionStorage` 猜测 |
| 观测支配规则（第四条：跨通道不能互证） | 上述信号源两两组合，且**故意让它们给出矛盾答案** | 异常偏爱发生在通道交界处：搜索说有三条，导航只有两条；索引时间戳与页面渲染耗时对不上 | 无需 UI。矛盾本身就是内容 |
| 默认稳定状态 | 骨架屏、`alt` 文本、图片加载失败的兜底文案、被 CSS 截断的省略号、`title` 属性里的完整值 | 玩家看到的"正常"其实是世界的兜底结果。它看起来和正常一模一样，因此"我看过了，是正常的"永远不构成证据 | 详见 4.3，**不要主动暴露这一点** |
| 过度稳定 | 浏览器 / CDN 缓存、`localStorage` 中持久化的旧版本、静态导出的固定产物 | 被反复访问的条目**以原样返回旧版本**。玩家以为看到的是最新内容，实际看到的是世界的化石 | 详见 4.2 |
| 细节漂移 | 见 9.2 的确定性变体选择 + 上述可见性门控 | 高成本属性变化：一段话里的数字、人名写法、标点、图片裁切比例 | 严禁随机字符替换（乱码），那是恐怖游戏最廉价的手法 |
| 局部缺失 | 元素存在但内容不可得、`alt` 为空、表格有一列没有表头 | 实体还在，但某个部位没有定稿。呈现为"这里本来就该是空的"，而不是"这里坏了" | 不得加红色边框、警告图标 |
| 区块边界 | 路由边界（词条页 ↔ 讨论页 ↔ 版本历史页之间）、静态导出的 chunk 边界 | 跨页跳转后，同一条目的措辞与上一页引用的不一致 | 边界异常只允许在此处发生 |

## 三、观测权重的三档实现（本项目最便宜的机制）

`01` 把"观测权重"定义成一次观测对通道状态产生约束的强度。世界观里它需要设备精度、频率、可复核性三要素。

**在浏览器里我们免费获得它。** 不需要数值系统，只需要按玩家真实行为分档：

| 档位 | 玩家真实行为 | 对应世界观表述 | 结算后果 |
|---|---|---|---|
| 低 | 页面挂在后台；快速划过；泛读；一次访问多个条目 | 余光观测、低权重观测 | 不结算。切片内不产生任何可见后果 |
| 中 | 正常滚动阅读、停留在视口内、翻页 | 有效观测 | 正常结算，允许漂移 |
| 高 | 精确选中某句并停留、复制某句 | 高权值观测单位 | 定稿：为该条目生成快照，从此原样返回，成为对照基准 |

**"高"档只由选中与复制构成。** 搜索定位、跨天回访、逐条比对看起来都像高强度观测，但它们的后果必须相反：搜索是导航、回访是时间推进、比对是同时阅读多个条目——把它们算作定稿，玩家越认真核对，世界就越早全部冻结，而这与"他为了确认而做的动作正是让他失去它的原因"（`§七` 第 5 条）恰好反过来。定稿必须是**稀缺的、玩家主动做的、做完之后不可撤销的**动作，一天里发生两三次就够。

这一档划分同时解决了玩家侧最难写的一环：**无需向玩家解释任何规则。** 玩家以为自己只是在阅读资料，实际上他的阅读方式正在决定世界怎么变。

## 四、三条通道的落地（4.2、4.3 优先级最高；4.1 明确不做）

### 4.1 剪枝热 → 只是文本里的一个词

世界观：候选状态每被剪掉一条，就有热量与噪声释放（`01` 9.4）。

**本项目不实现这条通道。** 剪枝热不产生真实负载、不读取温度、不模拟温度、不在页面上显示任何数值。它只以名词的形式出现在档案文本里：某份编辑须知提到"设备温度异常"，某条讨论串抱怨"开着这个站机器发烫"。玩家读到的是别人的记录，不是自己的体感。

理由：浏览器读不到设备温度，只能靠刻意做重的渲染去"造"一个热，而玩家无法把这个热归因到本网站；换来的只有性能投诉与电量消耗。留在文本里，成本为零，悬念不减。

边界（必须遵守）：
- 不做温度读数、热量进度条、状态灯，不做任何模拟温度变化的动画。
- 绝不在 UI 上提示"观测强度过高"。一个字都不要提。
- 词条里提到发热的句子属于**档案的既有叙述**，与玩家本次会话的行为无关，不随观测权重或轮次变化。

### 4.2 过度稳定 → 缓存返回旧版本

世界观：被高强度观测长期锁定的区域僵化；长期未更新的确认结果以原样返回，可能比现场更旧（`01` 10.6）。

实现：对高权重条目走缓存路径，永久返回同一份内容。同期其他条目在漂移，它不动。

呈现效果：玩家不会立刻察觉。他会在某天回头核对时，发现这一条**一个字都没变过**，而其他条目全变了。这一刻的认知是："是我没再来看它，所以它停在我离开的那天。"

这是本项目最好的一个反转：玩家以为的"存档"其实是"化石"。他每次回来，看到的都不是当前状态，而是自己最后一次高强度观测留下的原件。

不要解释它。让缓存这个技术事实自己完成叙事——它本来就是这么工作的。

### 4.3 默认稳定状态 → 兜底 UI

世界观：通道无法高精度结算时返回低成本稳定结果；其观感与"一切正常"完全相同（`01` 7.5）。

实现：骨架屏、`alt` 文本、图片加载失败时的占位文案、被截断的省略号、`title` 里更完整的字符串。

呈现效果：玩家看到的一直是"正常"。因此他所有的"我看过了、没问题"都是无效证据。这个性质是站内复核流程的制度基础，也是玩家最终意识到自己不可信的那一步。

**关键约束：不得把兜底做得像兜底。** 不能出现"内容加载失败"字样，不能有破图图标。兜底必须读起来像正常内容。玩家只应在事后（或者永远不应）意识到那不是正文。

## 五、不迁移清单

以下内容**明确不实现**。写在这里是为了防止实现层好心加回来。

| 不迁移项 | 理由 | 允许的存在形式 |
|---|---|---|
| 声学通道 | 无声学观测源，且任何"声音异常"都要求玩家戴耳机、按音量、点播放——这些是明示的游戏动作，直接破坏"这是一个网站"的前提 | 仅允许以**文字**出现：录音没有声音、转写稿里的 `[此处无人说话 4.2 秒]`、"声源无法绑定到任何设备"这类表述 |
| 热状态通道 / 剪枝热 | 浏览器读不到温度，"造热"只能靠真实渲染负载；玩家无法归因，只会当成网站卡、手机烫 | 仅允许以**文字**出现：见 4.1。不做温度读数，不做模拟 |
| 玩家侧预算数值（任何进度条、槽位、点数） | 数值系统让恐怖可计算；一旦可计算，玩家的最优策略就变成刷数值 | 无 |
| 异常等级 / 危险度 / 理智值 | 同上，且引入"变强"的快感，与心理恐怖方向相反 | 无 |
| 玩家可见的"规则说明" | `01` 是虚构 Wiki 的内部资料，不是写给玩家的攻略。教学式文案等于宣布这是游戏 | 站内文档自然语言中的零星条款（见第八节） |
| 区块边界的物理空间语义 | 网页没有物理空间，硬造"区块地图"会暴露模拟痕迹 | 用路由与文档结构承担"边界"含义（见第二节） |
| 监控增殖循环的系统化呈现 | 它是世界观层面的解释框架，不是体验；做成"加装摄像头"玩法会变成策略系统 | 仅在事件文案中出现一次 |
| 任何 jump scare、闪烁、全屏特效、扭曲人脸 | 与本项目唯一有效机制（玩家对自身记忆的怀疑）互斥 | 无 |
| 乱码 / 随机字符替换 | 廉价、可识别、且与"细节漂移"的世界观定义矛盾（漂移是高成本属性的变化，不是编码错误） | 无 |
| 承载通道 / 触觉观测（拖拽、表单输入、点"编辑"不提交引起的结构位移） | 位置与排序跳动在正文里读作"布局坏了"——本作最贵的失败模式正是玩家把异常当成故障；且位移不可撤销，一旦发生就污染 9.2 的单主干排版稳定性 | 无。相关词条与目录顺序保持登记顺序固定，不随任何动作重排 |

## 六、呈现层的禁令

### 6.1 视觉禁令

异常**不得**使用以下表现手法：`filter: blur()`、抖动/震动动画、红色描边、故障艺术（glitch）、倒转文字、变形的字体、突然的黑屏。

异常**只能**使用：截断、占位符、缺项、顺序变化、排版回流、措辞差异、`alt` 与正文不一致。

其中“占位符／缺项／`alt` 与正文不一致”在**图片位**上的具体形态是“只有 alt 的图片位”：数据侧只有 `alt` ＋ `prompt`、无 `src`，渲染为一个固定高度的边框加一行 alt 文字。两条约束：

- **填图不得改 `alt`**：alt 是已归档正文，图注与多处断言依赖它；填图只补 `src`。
- **图片位一旦填图，不得再以缺图作为该条目的“部分档”表现**——降级素材必须另行准备（`02` §3.4）。因此“刻意留空”的图位需显式登记（`08` §三）并由机制测试的白名单钉死，不得当作 bug 补上。
- **刻意留空全站仅一处**（`coldstore-photos-4`，2026-10-08 决策）：缺图的重量来自唯一性——
  同 `retainsId` 的纪律，“留存之所以有重量，正因为它只有一处”。12 有 1 无，那 1 处空位
  才读得出来；13 全空＝“本站没有图”，13 全有＝“没有缺”。

理由：前者要求玩家"注意到屏幕被动过"，后者要求玩家"怀疑自己的记忆"。本项目的恐怖完全依赖后者。

### 6.2 时序禁令

不得以"插入一帧 16–50ms 的异常画面"作为任何机制的实现手段。玩家看不到它，因此它对玩家不存在；能测到它的只有帧率，而掉帧不是恐怖。

合法做法：变化在**玩家切回来之后**的短窗口内生效，并且以正常渲染的一帧呈现。玩家的体验是"我一回来它就是这样"，而不是"我错过了什么"。

### 6.3 文案禁令

不得出现"检测到您的行为""观测强度不足""请刷新重试""系统提示""成就达成"。站内系统的口吻是**行政文书与工程记录**，不是游戏 HUD。

## 七、切片阶段的唯一完整感知回路

垂直切片**只要求跑通一条回路**。定义如下：

1. **真实行为**：玩家打开词条 A，滚动阅读，`IntersectionObserver` 记录他真正看过的段落。
2. **真实结算**：阅读过程中，页面把"哪些段落真正进入过视口、停留了多久"写入本地存储，作为下次访问的输入。无任何 UI 提示，玩家不知道自己被记录了。
3. **真实内容变化**：另一次访问中，玩家**看过**的那一段，出现一处措辞差异（细节漂移，确定性选择，见 9.2）。玩家没看过的段落不变。
4. **对照物**：玩家在同一站点里能找到一处他自己无法主动调用的历史痕迹（第八节的偏执回路），使"我记错了吗"无法被轻易排除。
5. **不可逆后果**：玩家用选中/复制定稿了某条目（第三节高档），该条目从此不再变化——并同时成为化石（4.2）。他为了确认而做的动作，正是让他失去它的原因。注意这一条**只由复制与精确选中触发**：回访与搜索属于第 3 步（推进轮次、产生变化），把它们同时写进第 3 步和第 5 步，整条回路就自相矛盾了。

第 4 步是整条回路的支点：**没有对照物，玩家真的记错时我们就什么都没了。** 切片验收只看这一条回路是否成立，不看其他。

## 八、偏执回路（对照物机制）

玩家可见文本必须提供至少一种"无法主动调用、只能被动撞见"的对照物。可选形式：

- 词条讨论页里另一人引用了该句的**旧版本**，且引用时间早于玩家第一次访问。
- 版本历史页存在一条玩家的编辑记录，但他没有编辑过。内容恰好是他心里想改的那一处。
- 搜索索引里该条目的摘要与页面正文差一个字。索引更新时间戳早于页面时间戳。
- 站内自己的复核页写着"经核对，本条目无变化"，**签名时间早于玩家第一次访问该页**（时间戳由构建时写入，见 `03 §4.5`）。

约束：
- 对照物**不解释自己**。不加"注意""发现异常""这里有蹊跷"。
- 对照物**不可被玩家主动刷新出来**。一旦可以主动调用，它就从证据变成了功能。
- 对照物的时间戳**只能指向过去，且早于玩家在该站的第一个痕迹**。曾有一条写成"签名时间为将来"：它在静态导出下无法自洽（页面不知道"现在"是几点，只能读玩家设备时钟，于是"将来"对每个玩家都不同、且清档即失效），更致命的是玩家一眼能看出这是伪造——指向将来的日期是排版错误，指向玩家到达之前的日期才是证据。
- 对照物允许与 `01` 第十二节例外登记项对应，但**不得在站内文本里指向该节**。
- 每幕至少引用一条登记项（`01` 12.2），引用方式是"让它再次发生"，不是"让它被说明"。

## 九、实现契约（对 L3 的硬约束）

### 9.1 术语污染禁令

`03` 及其产出代码中不得出现 L0 名词的直译标识符。禁止的命名示例：`observationBudget`、`visualChannel`、`pruningHeat`、`finalizeState`。

允许的命名风格：以技术事实命名——`driftIndex`、`lastVisitedAt`、`blockSnapshots`、`staleCacheKey`。

理由：代码是玩家可读的（静态导出、源码可能泄露）。以世界观术语命名的变量，等于把设定文档印在页面上。

### 9.2 确定性要求

任何"变化"必须能由 `(条目标识, 观测轮次, 停留门槛, 是否已定稿)` 完全决定。**禁止运行中随机，也禁止用 hash / PRNG 从轮次推导文本。**

不推荐 seeded hash 的理由不是它不确定，而是它**对作者不可读**：`hash(blockId#round) % variants.length` 让"第 3 天玩家读到哪一句"这件事无法在数据里被看见，于是作者在看不见的前提下写出了与对照物相撞的数字。要求改为**变体按轮次显式声明**（`{ round, text }[]`），轮次与文本的对应关系是数据，不是算法。取模、随机、按玩家标识分桶选文本，三者一律禁止。

且**玩家实际看到的版本必须能由持久化状态确定性重建**——是"可重建"，不是"必须持久化"。需要落盘的只有事实（看过多久、哪天来过、定稿过的原文），版本本身是这些事实的函数；把函数结果再存一份，就多出一个会与事实矛盾的缓存。之所以必须可重建，理由有两条：
- Next.js 静态导出的 hydration 一致性——服务端渲染与客户端首帧必须算出同一版；
- 恐怖的前提是"世界只有一条主干"（`01` 9.2 不可改写历史）。如果玩家刷新一次内容就回滚，前面所有怀疑全部作废。

### 9.3 状态订阅与日志

- 字段级 selector 订阅，禁止全量 store 订阅。全量订阅会让每次信号到来时整页重渲染，把一次局部变化放大成"页面自己在动"。
- 行为日志必须是有界结构（环形缓冲或按窗口聚合）。日志的目的是提供对照物，不是记录一切；无限增长的存储会在移动端自己造成卡顿，而那种卡顿与任何结算无关，会被玩家当成异常。

### 9.4 多标签页

跨标签页一致性统一走 `BroadcastChannel`。`sessionStorage` 按标签页隔离，用它统计多标签行为等于猜。

### 9.5 持久化边界

`localStorage` 承担"世界记忆"。清档必须是一个**叙事事件**，不是设置项按钮（`02` 的隐藏终章机制）。不得提供"重置进度"的显式入口。

## 十一、结算收据与判定边界

### 11.1 行为 → 判定 → 后果（全表）

回访、定稿与“热”的关系散落在 `01` 的 2.7 / 10.6 / 9.4 三节，此处一次对齐。三条并不冲突——它们分属三个层：单次观测强度（2.7）、记录的返回方式（10.6）、定稿耗散的现场（9.4）：

| 玩家行为 | 判定 | 后果 |
|---|---|---|
| 首访精读（视口停留 ≥ 门槛） | 资格事件（时间连续性） | 该块**有资格**参与变化；此后跨天回访才兑现 |
| 同日回访 | 不判定 | 无痕——给“我记错了”留出口 |
| 跨天回访 | 轮次 +1（上限 `ROUND_MAX`） | 未定稿块漂移；**已定稿块纹丝不动**（快照优先于轮次） |
| 选中 / 复制（同块、≥ 6 字） | 定稿（高权重观测） | 永久返回原件（化石）+ 成为对照基准 + 引出一句“热”的说法（见 4.1，仍只是文本） |
| 后台挂着 / 划过 | 不结算 | 无痕——既不留痕，也不产生任何变化 |

口径（三句话，全站唯一）：**回访不改权重，只改资格；定稿改权重、终结资格；确认（定稿）越多，“热”越多。**

实现层的对齐点是 `resolve.ts` 的判定顺序（定稿 → 轮次 → 阅读层级），该顺序为不变量，`golden` 测试 1–5 即它的看守。任何在组件里重开条件判断的写法都违反本节。

### 11.2 结算收据（不解释 ≠ 不确认）

**“不解释”是对含义的纪律，不是对后果的纪律：**

- **含义必须不可见**：站方永不说出后果意味着什么，不给因果、不给评述；
- **后果必须可见**：玩家的每个不可逆动作，都要在世界里留下可被他自己撞见的差异。没有差异的登记点，玩家收不到“我做了什么”的任何回应——那不是不解释，是没收到。

收据的三种合法形态（三选一，允许叠加）：

1. **解锁**：完成条件后，新内容出现在他的渠道里（例：还原台帧重建、张工手记·第二页）；
2. **差异**：同一条目对他的呈现不同（例：须知第 8 条、玩家台账）；
3. **缺席 / 互斥**：他的选择使某些文书**只出现一份**、另一些不再出现（例：《复核名录》增列与停列两页互斥，互为对方的缺席）。

禁用形态：任何**系统口头确认**（“你拼对了”“选择已生效”一类解释性语句）。收据由**文书本身**承担，不由答复承担——征询页写着“不作答复”，这不是矛盾：改变的不是答复，是世界。

新登记点的自查题：**这个动作在世界里留下了哪一种收据？** 答不上来的登记点不上线。
