## 〇、切片目标

**不是"30 分钟可体验原型"。** 切片只验证一个假设：

> 玩家回访同一个词条时，能不能注意到他真正读过的那一段变了，并在注意到的那一瞬间先怀疑自己的记忆。

假设不成立，后面所有幕次都不要开工。

因此本切片的一切设计围绕两个必要条件：

1. **变化只发生在玩家真正看过的位置**（`04 §2` 视觉通道行）。否则玩家无法把它与自己记错区分，恐怖退化为随机彩蛋。
2. **存在一个玩家无法主动调用的对照物**（`04 §8` 偏执回路）。否则"我真的记错了"永远是安全出口。

### 切片范围（明确边界）

| 必做 | 不做 |
|------|------|
| 3 个词条（新编辑须知 / 北环路地下通道 / 11·29 电子屏异常） | 预算、等级、进度、成就、任何数值 |
| 1 份动态日志（真实行为，有界） | 多通道面板 UI、任何仪表盘 |
| 1 次回访触发的差异 | blur / 抖动 / 噪点 / glitch / 乱码 |
| 1 次"以原样返回旧版本"（化石） | 音频、录音播放 |
| 1 个对照物 | 剪枝热的任何实现（真实负载、发热、温度读数，见 §五） |
| — | 倒计时、时钟门（21:17 一类）；白昼馆、双窗、签收单（Phase 2+） |

首页观感必须**完全正常**。切片完成度的第一判据是"测试者前五分钟以为这是个真网站"。

## 一、技术栈

- Next.js 14+（App Router，**静态导出** `output: 'export'`）
- TypeScript
- Tailwind CSS
- Zustand + `persist`（localStorage）
- 部署目标 Vercel；包管理 npm

```bash
npx create-next-app@latest guance-archive --typescript --tailwind --app --src-dir --no-import-alias
cd guance-archive
npm install zustand
```

### 静态导出带来的三条约束（必须先读）

1. **没有服务端权威。** 所有"系统结论"由本地生成。这不是缺陷，是本项目的前提，站内文本口吻按 `04 §6.3` 执行（行政文书与工程记录，不是游戏 HUD）。
2. **首屏内容必须是可预渲染的。** 一切依赖 localStorage 的内容变化都必须走第 3.3 节的 hydration 方案，不允许用 `mounted` 闪烁法。
3. **变体内容全部进构建产物。** 静态导出意味着玩家查源码可以看到所有变体文本。这是可接受的风险，但有一条硬要求：**变体本身不得含解释性文本**，不得出现"这是异常版本"之类的标记，字段名不得带世界观词。

### 2.2 数据流

```
浏览器真实信号
  ├─ IntersectionObserver：哪些 blockId 真正进入视口并停留
  ├─ selectionchange / copy：精确读取过的 blockId
  ├─ 路由序列 + 时间戳：第几次访问、是否跨自然日
  └─ BroadcastChannel：其他标签页的真实存在
        ↓
  traceStore（有界、持久化）
        ↓
  WorldState = { round, seenMs, snapshot }   ← 全部由持久化状态推导
        ↓
  resolve(block, world) → { text, variantIndex, tier }   ← 唯一判定出口
        ↓
  VariantSpan 只渲染返回值，不再自行加任何条件
```

**没有任何 `setInterval` 记账。** 所有推进由真实事件驱动。玩家挂着一个不动的页面，世界不许发生变化（`04 §1.2`）。

### 3.1 类型（`src/types/index.ts`）

### 3.2 持久化状态（`src/lib/traceStore.ts`）

```typescript
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

const TRACE_CAP = 300;            // 有界：超出丢弃最旧（04 §9.3）
const SEEN_CAP = 400;
const SNAP_CAP = 200;             // 高档观测是稀缺资源，但容器仍需上限
const TAB_TTL_MS = 9000;          // 3 个心跳周期（心跳间隔 3000ms）

/**
 * 自然日必须取**本地日**，不是 UTC 日：`toISOString().slice(0,10)` 在 UTC+8 下把本地 00:00–08:00
 * 归入前一天，"隔天再来才推进轮次"会在凌晨静默失效。`sv-SE` 稳定输出 `YYYY-MM-DD`。
 */
export function localDay(d: Date = new Date()): string {
  return d.toLocaleDateString('sv-SE');
}

export interface Snapshot {       // 化石条目
  key: string;                    // blockId
  text: string;                   // 当时所见，原样保存
  at: number;
}

export interface TraceState {
  // —— 真实信号 ——
  seen: Record<string, number>;       // blockId -> 累计在视口内的毫秒数（有上限）
  visits: Record<string, { n: number; dn: number; lastDay: string; lastAt: number; firstAt: number }>;
  days: string[];                     // 出现过的自然日，最多 60 项
  actions: { at: number; kind: string; target: string }[];  // 环形缓冲
  tabs: Record<string, number>;       // BroadcastChannel 心跳
  /** 唯一的高档记录：存在即"已钉住"。不再有第二个 `pinned` 数组。 */
  snapshots: Record<string, Snapshot>;

  markSeen(id: string, ms: number): void;
  enterEntry(slug: string): void;
  log(kind: string, target: string): void;
  recordTab(id: string): void;
  pruneTabs(): void;              // 页面重新可见时调用一次，清理已关闭的标签页
  snapshot(id: string, text: string): void;
  resetAll(): void;               // 不提供 UI 入口，见 04 §9.5
}

export const useTrace = create<TraceState>()(persist(/* 初始状态全为空 */, { name: 'ga-trace-v1' }));
```

**实现要求（写法不限，下列每条必须成立）：**

- **全部有界。** `actions` 最多 `TRACE_CAP` 条，超出丢最旧；`seen` 最多 `SEEN_CAP` 个 key，超出丢累计时长最小的；`snapshots` 最多 `SNAP_CAP` 项，超出丢 `at` 最早的；`days` 最多 60 项，超出丢最旧。单个 `seen[id]` 的累计值封顶 600_000ms。
- **`enterEntry(slug)` 是轮次的唯一来源。** 每次进入词条页调一次：`n`（会话数）总是 +1；`dn`（不同自然日数）仅当 `localDay() !== lastDay` 时 +1；同时把当天追加进 `days`（已存在则不追加）。
- **`snapshot(id, text)` 一旦写入永不覆盖**（`04 §4.2`）：已存在就直接返回，不更新文本也不更新时间戳。
- **`tabs` 是租约，不是名单。** `recordTab(id)` 写入当前时间戳并剔除超过 `TAB_TTL_MS` 未刷新的项；`pruneTabs()` 做同样清理，在页面重新可见时调用一次。不清理的话，"同一时间存在其他查阅会话"这条硬证据就会虚报已关闭的标签页。
- **`resetAll()` 清空全部字段，但不提供任何 UI 入口**（`04 §9.5`）。
- 持久化 key 固定为 `ga-trace-v1`。

**轮次稳定性（`04 §9.2`）：** 不额外存"已生效轮次"。`roundFor()` 只由持久化的 `visits[slug].dn` 推导，同设备同词条的变体天然跨会话稳定；把轮次写回 store 是多余的自造状态，禁止。用 `dn`（自然日数）而非 `n`（会话数）：后者玩家可以自己刷新加速。

**订阅规范（强制）：** 组件一律用字段级 selector，禁止 `const s = useTrace()` 全量订阅（`04 §9.3`）——全量订阅会让每次信号到来时整页重渲染。

```tsx
const seen = useTrace((s) => s.seen[blockId]);              // 正确
const snapshot = useTrace((s) => s.snapshots[blockId]?.text); // 正确
const s = useTrace();                                          // 禁止
```

### 3.3 变体解析：确定性 + hydration

```typescript
// lib/resolve/hash.ts —— 不用 Math.random，不用日期参与
export function hash32(input: string): number {
  let h = 0x811c9dc5;
  for (let i = 0; i < input.length; i++) {
    h ^= input.charCodeAt(i);
    h = Math.imul(h, 0x01000193);
  }
  return h >>> 0;
}
```

`hash32` 只用于两处：生成玩家稳定标识（§4.4）与打散列表顺序。**不得用它选择文本**（如 `hash32(id#round) % count`）：那样作者在写数据时看不见"第 N 天会命中哪一句"，可能让正文与 §4.5 对照物撞出同一个数字，张力消失且构建、测试都不报错。变体一律按轮次显式点名（`{ round, text }[]`）。

```typescript
// lib/resolve/roundFor.ts
import { useTrace } from '@/lib/traceStore';

/** 轮次上限。切片只覆盖 3 次跨天推进，第 4 天起世界不再变化（每块 2 个变体 × 3 轮已是单人可完成的量）。 */
export const ROUND_MAX = 3;

/**
 * 轮次 = 该条目跨自然日的回访序号（dn = 访问过的不同自然日数）。
 * 以"日"为单位而非会话（刷新无法加速，04 §2）；首轮恒为 0（首次访问绝不出现差异）；
 * 同日多次回访不推进（给"我记错了"留出口）。
 */
export function roundFor(slug: string): number {
  const v = useTrace.getState().visits[slug];
  return roundFromDn(v?.dn ?? 1);
}

/** 纯函数入口：供组件内已订阅 `dn` 的 hook 使用，避免在 render 里读 store。 */
export function roundFromDn(dn: number): number {
  return dn <= 1 ? 0 : Math.min(ROUND_MAX, dn - 1);
}
```

### 3.3.1 唯一判定出口 `resolve()`

全部门控（定稿优先、首轮不漂、没看过不漂、缺项不漂）**只出现在这一个函数里**，组件内不得再出现 `if (round ...)`、`if (seen ...)`。切片由二十多个这样的小条件组成，散落在组件里时漏掉任何一条都不报错，只表现为"这游戏有点怪"；收进一个纯函数后，§8.4 的黄金测试能一次性钉住。

```typescript
// lib/resolve/resolve.ts
import type { ContentBlock } from '@/types';
import { tierOf, type Tier } from '@/lib/reader';

/** resolve 的唯一输入，字段全部来自持久化状态或真实信号。fixture 注入（§8.5）替换的就是这里的输入，不是判定逻辑。 */
export interface WorldState {
  round: number;          // roundFromDn(visits[slug].dn)
  seenMs: number;         // seen[blockId]
  /** snapshots[blockId]?.text。存在即"已定稿"，不再有并行的 `pinned` 布尔量（两个容器表达同一事实必然漂移）。 */
  snapshot?: string;
}

export interface Resolved { text: string; variantIndex: number; tier: Tier }

const MIN_ROUND_DEFAULT = 1;

/**
 * 判定顺序即优先级，任何一条都不得在别处重复实现：
 *  1. 定稿优先——有快照的位置原样返回原件（04 §4.2 化石）。
 *  2. 轮次未到 minRound——规范版。首轮（round = 0）恒不漂移，这是切片的地基。
 *  3. 档位为 low（划过 / 泛读 / 后台未结算）——规范版。没真正看过的人不许看到变化。
 *  4. 取"不超过当前轮次的最大已声明轮次"：漂移只前进、不回退，
 *     因此作者可以只声明 round 1、2 而让该块在第 3 天保持上一版，
 *     绝不允许出现"第 4 天悄悄退回规范版"。
 */
export function resolve(block: ContentBlock, w: WorldState): Resolved {
  const tier = tierOf(w);
  if (w.snapshot !== undefined) return { text: w.snapshot, variantIndex: -1, tier };

  const minRound = block.minRound ?? MIN_ROUND_DEFAULT;
  if (w.round < minRound || tier === 'low') return { text: block.text ?? '', variantIndex: -1, tier };

  const vs = block.variants ?? [];
  let hit = -1;
  vs.forEach((x, i) => {
    if (x.round >= minRound && x.round <= w.round && (hit < 0 || x.round > vs[hit].round)) hit = i;
  });
  if (hit < 0) return { text: block.text ?? '', variantIndex: -1, tier };

  return block.driftable
    ? { text: vs[hit].text, variantIndex: hit, tier }
    : { text: block.text ?? '', variantIndex: -1, tier };
}
```

```typescript
// lib/resolve/useResolved.ts —— 组件与 resolve 之间唯一的桥
'use client';
import { useTrace } from '@/lib/traceStore';
import { resolve, type Resolved } from './resolve';
import { roundFromDn } from './roundFor';

/** 字段级订阅（04 §9.3）：只订阅这三个值，任一变化才重渲染这一个 span。 */
export function useResolved(block: ContentBlock, slug: string): Resolved {
  const seenMs = useTrace((s) => s.seen[block.id] ?? 0);
  const snapshot = useTrace((s) => s.snapshots[block.id]?.text);
  const round = useTrace((s) => roundFromDn(s.visits[slug]?.dn ?? 1));
  return resolve(block, { round, seenMs, snapshot });
}
```

`roundFor(slug)` 与 `roundFromDn(dn)` 是同一个纯函数的两个入口——前者读 store，供组件外的路径（搜索摘要、历史摘录、构建期）使用；后者接受已订阅的 `dn`，供 hook 使用。**轮次永不写回 store**：它由 `dn` 推导，因此"同一台设备上同一词条的变体可复现"这一 `04 §9.2` 的要求，由持久化状态本身满足。

```tsx
// components/VariantSpan.tsx —— 关键文件：它只渲染，不判定
'use client';
import { useResolved } from '@/lib/resolve/useResolved';
import type { ContentBlock } from '@/types';

export function VariantSpan({ block, slug }: { block: ContentBlock; slug: string }) {
  const out = useResolved(block, slug);
  return (
    <span suppressHydrationWarning data-bid={block.id}>
      {out.text}
    </span>
  );
}
```

**这个组件里不许出现任何条件判断。** 门控写在组件里时，"漏了轮次闸门"这类缺陷逐行审查也看不出来（语法与引用全都正常），只会表现为"首次访问就看到了漂移"。收进 `resolve()` 之后，同一缺陷在黄金测试第 1 条上必然失败。

服务端渲染规范版，客户端 hydration 时同步从 localStorage 读出解析结果，`suppressHydrationWarning` 用在叶子文本节点上正合适。**不得改用 `mounted` 状态延迟渲染**——那会让玩家亲眼看到文字在眼前换掉，摧毁"我记错了吗"这个唯一有效的问句（`04 §6.2`）。

### 3.4 信号采集

四个模块，各做一件事，全部只写入 `traceStore`。下面给的是**契约**，不是参考实现——写法自行决定，但列出的每条约束都必须满足。

**`useSeenBlocks()`** — `lib/signals/useSeenBlocks.ts`

- 用 `IntersectionObserver`（`threshold: 0.6`）观察页面上所有 `[data-bid]` 元素。
- **逐元素计时**：记住每个元素进入视口的时刻，划出视口时结算这一段时长，调 `markSeen(id, ms)`；单段最多计 30s。
  用"观察者创建时刻"当全局起点是错的——每个划过的段落都会拿到同一个巨大值，低档与中档的分界随之消失（`04 §3`）。
- 结算点只有两个：划出视口、页面转入后台（`visibilitychange`）。
- `document.visibilityState !== 'visible'` 时不结算。
- 页面回到前台时顺手调一次 `pruneTabs()`，清理已关闭标签页的租约。两件事共用同一个可见性监听点，因为都由"可见性变化"这一真实事件触发。

**`useHighPrecisionActions(slug)`** — `lib/signals/useHighPrecisionActions.ts`（高档观测 = 定稿）

- 同时监听 `copy` 与 `selectionchange`，两者都能触发定稿。只写 `copy` 等于让 `04 §2/§3` 里的"精确选中"在实现层不存在。
- 结算条件（全部满足才算）：
  - 选区非折叠，且长度 ≥ 6 字；
  - 选区整体落在**同一个** `[data-bid]` 内——跨块选区属于泛读，不结算；
  - 焦点不在 `input` / `textarea` / `contenteditable` 内——在搜索框里选中几个字不是阅读行为；
  - `selectionchange` 需**选区稳定 400ms** 后才结算，避免拖选途中触发；
  - 800ms 内去抖：一次复制会同时触发两个事件。
- 定稿只有两步：`snapshot(bid, text)` 与 `log(kind, \`${slug}:${bid}\`)`，`kind` 取 `'copy' | 'select'`。没有第三步。
- **快照文本一律从 DOM 取**（`textContent`），不从数据文件取。玩家看到的可能已经是变体；从数据取会让化石永远等于规范版，机制自我取消。
- 少了这些门槛，拖过三个段落就会把它们全部定稿，`04 §4.2` 的化石会变成"随便划一下就能造一堆"。

**`useVisitTimeline(slug)`** — `lib/signals/useVisitTimeline.ts`

- 挂载时 `enterEntry(slug)` + `log('visit', slug)`；卸载时 `log('leave', slug)`。
- **只记录，不推断。** 轮次推进一律由 `dn` 完成（见 3.3）。
- 卸载时要留下一条真实的离开记录：日志页显示的是"你何时离开的"，不是编出来的"会话结束"。

**`startTabSync(onPeer)` / `tabId`** — `lib/signals/tabSync.ts`

- 多标签一律用 `BroadcastChannel`。不得用 `sessionStorage` 猜：它按标签页隔离，用它统计等于凭空捏造（`04 §9.4`）。
- 每 3 秒广播一次自身 id，收到别人的 id 时回调 `onPeer(id)`。调用方需在 `onPeer` 里 `recordTab(id)`，并在自身启动时 `recordTab(tabId)`。
- 这是全项目**唯一允许的 `setInterval`**：只广播身份，不扣减任何东西、不参与内容选择。验收里"无 `setInterval` 式预算扣减"针对的是每 5 秒 `consumeBudget(...)` 那种写法。
- id 用 `crypto.getRandomValues` 生成，不用 `Math.random`——不让任何一处随机数与内容选择沾上关系。
- 白送的现象：玩家开了第二个标签页，站内文书里就多出一个真实标识。

### 3.5 权重档位（`lib/reader.ts`）

`04 §3` 的三档在代码里是一次判定，且**只被 `resolve()` 调用**——组件不得直接调它。

```typescript
// lib/reader.ts
export type Tier = 'low' | 'mid' | 'high';

// 停留门槛：低于此值视为"划过"，不结算（04 §3 低档）
export const SEEN_GATE_MS = 1500;

/** 只回答"这一次阅读算不算数、算多重"，不回答"该显示哪一版"。
 *  入参只接受真实信号或持久化状态的直接投影，不接受推导值（多余入参会让人以为三档还有别的口径）。 */
export function tierOf(w: { seenMs: number; snapshot?: string }): Tier {
  if (w.snapshot !== undefined) return 'high';        // 有原件 → 已定稿
  if (w.seenMs < SEEN_GATE_MS) return 'low';          // 划过、泛读、后台未结算
  return 'mid';
}
```

档位只影响**结算行为**（低档不结算、中档允许漂移、高档定稿并生成化石），不进入任何玩家可见文本，日志页不显示档位。

"跨天回访"**不在** `tierOf` 里：它推进轮次（`roundFor`），不是档位。隔天回来是让条目**有资格**在新轮次里变化，不是让它**退出**变化（`04 §2 / §3`、`02 §4.7` 同口径）。若把跨天回访也算作定稿，玩家第 2 天回访就会锁死所有读过的词条。

### 3.6 化石

```typescript
// lib/resolve/snapshots.ts
// 对应 04 §4.2：过度稳定 = 以原样返回。首次定稿后永久返回原件，此后不再更新。
import { useTrace } from '@/lib/traceStore';

export function staleOr(blockId: string, current: string): string {
  return useTrace.getState().snapshots[blockId]?.text ?? current;
}
```

`staleOr` 是组件之外那条路（搜索摘要、历史摘录、`/verify` 正文）用的非 hook 版本，与 `VariantSpan` 订阅同一份 `snapshots`，不得各自维护缓存。**它必须有真实调用点**（搜索页摘要与历史页摘录都经它取文），否则"化石只在一处生效"会被玩家当成随机故障。任何以"当前最新版"重写 `snapshots` 的代码都违反 `04 §4.2`。

**`04 §4.3`（默认稳定状态 → 兜底 UI）：L3 侧不设独立的兜底文案字段或组件。** `resolve()` 的返回值永远就是正文本身，没有第二条返回路径。约束不变：不得出现"加载失败""内容不可用""数据缺失"字样，不得有破图图标、红色边框、警告色。

### 4.5 对照物（`/verify/north-loop-tunnel`）

一个**没有入口**的页面（不出现在导航、不出现在相关词条、不参与搜索），只能从两个地方到达：

1. 编辑历史某条记录的"复核"字样本身是链接（每幕最多一处此手法，切片就用这一处）。
2. 站内搜索"北环路 复核"可命中（命中即成立，不提示）。

页面内容：

> ## 复核记录
>
> 复核对象：北环路地下通道 · 基础设施
> 复核时间：2024-12-02 11:40
> 复核结论：经核对，本条目自上次复核以来**无变化**。
> 上一版本摘录："…电子广告屏（4 块）、导向标识系统和紧急呼叫装置。监控点位共 15 个，信号接入城北新区综合管理平台。"
>
> 复核人：程露
> 本页由系统生成，不接受编辑。

这一页是切片的**支点**，做三件事：

- 给玩家一个他自己无法生成的对照物（"共 15 个点位"写在一份正式文书里）。他若发现正文写 16，"我记错了"这个出口就被堵住一半。
- 签名人程露第一次出现是**文书里的一个名字**，不是角色介绍（`02 §4.9`）。
- 复核时间戳早于玩家第一次访问。

**不得在此页添加任何提示、强调色、"发现异常"字样。** 它必须看起来像一张无聊的表格。

它同时是化石机制的载体：摘录从 `snapshots` 取，一经生成永不变——即使正文在漂移，这份"无变化"的结论永远成立（`04 §4.2`）。

#### 两个必须写代码兑现的前提

**其一，摘录文本走快照，不走数据文件**（写死在 `data/` 里它就只是个常量）。摘录段用 §3.6 的 `staleOr` 取文：

```tsx
// app/verify/[slug]/page.tsx
import { staleOr } from '@/lib/resolve/snapshots';
import { VERIFY_BLOCKS } from '@/data/entries';

export default function VerifyPage({ params }: { params: { slug: string } }) {
  const b = VERIFY_BLOCKS[params.slug];
  return <p className="text-[15px] leading-7 text-gray-900">{staleOr(b.id, b.text ?? '')}</p>;
}
```

**其二，`snapshots` 是空表启动的**：它只由复制/精确选中写入。一个从不复制的玩家打开这一页会看到空白。因此对照物页必须在客户端首次挂载时**幂等地播种**自己的快照：

```tsx
'use client';
function useSeedVerify(id: string, canonical: string) {
  useEffect(() => {
    const s = useTrace.getState();
    if (!s.snapshots[id]) s.snapshot(id, canonical);   // snapshot() 内已幂等，此处判空仅为省一次 set
  }, [id, canonical]);
}
```

播种必须在 client effect 里，不能在模块顶层——`snapshots` 来自 localStorage，服务端没有它，在渲染路径读会留下一个永久性空段。播种之后这一页就冻结了：正文漂到哪一版都不影响 `staleOr` 的返回。

#### 静态导出下这一页必须显式生成

`output: 'export'` 不会为动态段预渲染任何未知值。`/verify/north-loop-tunnel` 若依赖按需渲染，线上会得到一个 404，而玩家永远不会知道自己那一次点击本该看到东西——支点直接丢失：

```typescript
// app/verify/[slug]/page.tsx
import { VERIFY_SLUGS } from '@/data/entries';

export function generateStaticParams() {
  return VERIFY_SLUGS.map((slug) => ({ slug }));
}
export const dynamicParams = false;   // 未声明的 slug 一律 404，不许按需渲染
```

`/entry/[slug]` 与 `/history/[slug]` 同理——切片只有 3 个词条，全部枚举没有任何代价。**任何 `[slug]` 页面缺少 `generateStaticParams` 即判验收不通过**（§8.2 第 6 项）。

#### "15" 是本页独占的数字

`监控点位共 15 个` 之所以能用，前提是**没有任何变体会在同一位置写出 15**。§4.2 的 `infra` 变体因此走 16 → 14 → 13，跳过 15。

但"独占"必须是一份**声明**，不能是从文书文本里正则抽出来的集合：那样 `2024-12-02 11:40` 会被拆成一堆数字段去比对，`03:26:15` 里的 `15` 误报、单个 `4` 命中所有含 4 的时间串，一条噪声过大的检查最终会被关掉。因此对照物页显式声明它独占的值：

```typescript
// data/entries.ts
/** 复核文书中真正承担"对照"功能、因此被本页独占的值。
 *  只有参与对照的数才写在这里：时间戳与日期不属于对照物。 */
export const RESERVED_NUMBERS = ['15', '4 块'];
```

由 §8.4 黄金测试第 6 条机器核对：**任何词条的任何变体文本，都不得让 `RESERVED_NUMBERS` 中的任何一项作为独立数值出现。** 另配一条反向检查（独占表每一项都必须真的出现在对照物文书里），防止作者改了文书数字却忘了改独占表、让第 6 条静默退化成永真断言。

## 五、剪枝热：本切片不实现

对应 `04 §4.1`、`04 §五`。剪枝热是**纯剧情设定**，不是需要实现的功能。

不要写以下任何东西：
- 不做真实 CPU / 渲染负载，不建 worker，不做"发热窗口"。
- 不读取、不模拟、不显示温度；没有温度读数、热量条、状态灯、模拟升温动画。
- 不在 UI 上出现"负载""变慢""观测强度""请等待"。
- 不需要 `lib/paint/` 目录，不需要 `heatBurst`。

允许的存在形式只有一种：**档案文本里的叙述**。例如词条底层版本里那句"广告屏旁有轻微温升。断电后三分钟内局部温度上升 2.4 摄氏度"（见 §4.3）。那是档案里别人写的记录，与玩家本次会话的行为无关，不随观测权重或轮次变化，也不得在任何 UI 里被指向。

## 六、渲染层与视觉规范

### 6.1 整体

沿用原稿配色与布局（`#FFFFFF` / `#F9FAFB` / `#111827` / `#2563EB` / `#E5E7EB`；1200px 居中、左导航 240、右栏 280；系统字体）。目标是不加装饰的现代 Wiki / 文档协作平台。

新增两条：

- **首页与词条页在视觉层次上不得有任何差异。** 不用强调色标出可变内容，不给变体加 class，不留 `data-anomaly-level` 这类属性（原稿有，删除）。玩家用样式面板能查出哪些文字被替换过，这是穿帮。
- 变体替换前后**行高必须一致**，避免排版回流被误读为特效。数字/用字类替换天然满足；第三处（热点名省略）会导致行宽变化，需接受——它是本切片唯一一次允许的回流。

### 6.2 CSS 禁令（对应 `04 §6.1`）

原稿的 `.anomaly-3`（`filter: blur(0.5px)` + `subtle-shake`）与 `@keyframes subtle-shake` **整段删除**。同样禁止：噪点、故障效果、倒转文字、透明度渐变、红色描边、黑屏闪烁、`letter-spacing` 微调（那是 CSS 在动，不是世界在动）。

允许的"异常"表现只有六种：内容截断（省略号）、字段为空、表格缺列、只有 `alt` 的图片位、顺序变化、措辞差异。

```css
/* 全项目仅此一类与"异常"相关，且它做的是排版而非表演 */
.trunc { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

### 6.3 文案禁令（对应 `04 §6.3`）

不得出现："检测到您的行为""观测强度不足""请刷新重试""系统提示""成就""已解锁"。系统口吻是行政文书与工程记录。

## 七、开发顺序

每步结束必须可运行、可回看。

1. 初始化 + 静态导出配置（`output: 'export'`，`trailingSlash: true`）；**所有 `[slug]` 路由同时写好 `generateStaticParams` 与 `dynamicParams = false`**，即使此时页面还是空的。漏掉这一步的代价要到部署后才暴露，而暴露形式是 404，没人会把它归因于配置。
2. 类型与词条数据（先把 3 个词条的规范版写完，**变体此时留空**）
3. 布局、首页、词条页、搜索页 —— 全部为纯静态正常 Wiki，此时请给同事看一眼问"这像不像真项目站"
4. `traceStore`（有界 + persist）与字段级 selector 规范
5. `resolve.ts` + `roundFor.ts` + `tierOf` —— **纯函数，先于任何组件**；同时写 §8.4 的黄金测试和 §8.5 的 fixture 注入。此时还没有 UI，测试即可跑完。
6. `useResolved` + `VariantSpan`（此时组件仍是零条件；hydration 验证：强制刷新、返回上一步、多标签三种路径下内容稳定）
7. `useSeenBlocks` / `useVisitTimeline` / `tabSync` / `useHighPrecisionActions`
8. 填入变体（3 + 2 处，按 §4.2/§4.3 的轮次表逐条点名），跑一遍黄金测试，确认首轮访问永不出现差异
9. `snapshots` + `staleOr`：复制一次 → 隔天回访 → 该句一字不变，而其他处在漂
10. `/trace` 页（真实行为，无任何数值）
11. `/verify/north-loop-tunnel` 对照物页（无入口 + 快照播种）
12. `SiteNotice`：第二次会话开始时投一条站内通知（**不是弹窗**，是首页一条列表项），正文三遍重复"你查阅的内容不会因为你的查阅行为而改变"
13. 真人测试（第八节），不合格回到第 8 步改强度

第 5 步排在所有采集与渲染之前：判定收进纯函数后，切片最贵的一类缺陷（"某条门控没生效，但没有任何东西报错"）才能在无浏览器、无设备、无测试者的情况下十秒内证伪。

## 八、验收标准

### 8.1 真人感知指标（唯一硬门）

3 名不知情测试者（不知本项目目的、不看本文档）：

1. 前 5 分钟不得有人提出"这是个恐怖游戏"。若有人提出，第 3 步未完成，先修观感。
2. **第一次变化无人察觉属正常，不判失败。**
3. 第二次变化后：至少 **2 人主动回头核对**（往上滚、点编辑历史、搜索、开第二个标签页比对）。
4. 至少 **1 人说出"刚才是不是变了"或等价表述**（"我记的不是这个""是不是缓存问题"）。
5. 至少 **1 人在察觉变化后改变了自己的行为**（放慢滚动、离开页面、把某句复制留存、关掉另一个标签页）。第 5 条是本切片唯一无法伪造的指标——它证明玩家开始把自己的阅读当成有后果的动作。
6. 对照物：至少 **1 人自行找到 `/verify` 页**（通过历史页链接或搜索）。若无人找到，把该链接的可见性提高一档，但**不得加提示**。

2–5 条中任意一条不达标，**不得进入 Phase 2**。未达标时不扩建内容，先修感知（`02 §八`）。

**测试协议（不可压缩）：** 轮次由 `dn`（跨自然日数）驱动，所以这项测试天然要占用至少 3 个自然日——每天一次自由浏览，测试者不知道自己被要求回来，也不得被提醒回来。任何"改代码让变化在一次会话内连续发生三次"的做法都会同时毁掉测试与产品；评审时的快速演示一律走 §8.5 的 fixture 注入，**不得改判定逻辑、不得给 `Date` 打补丁、该开关不得进入构建产物**。

### 8.2 技术指标

- [ ] 全程无 `setInterval` 式预算扣减；无 `Math.random()` 参与内容选择
- [ ] 首次访问、以及同一天内任意次数的重复访问，两种路径下内容与规范版完全一致（轮次只由 `dn` 推进）
- [ ] 同一 `(blockId, round)` 在任意时刻、任意标签页解析出同一变体
- [ ] 玩家未进入视口的段落永不变化（用 `IntersectionObserver` 面板验证）
- [ ] 复制过的句子此后不再变化，且与当时所见逐字一致
- [ ] hydration 无警告、无可见闪烁；`build` + `serve out` 静态产物下表现一致
- [ ] **`out/` 下存在全部 `[slug]` 路由的静态页**：`entry/`、`history/`、`verify/` 三类各有 3 份 `index.html`，即 `ls out/*/north-loop-tunnel/index.html` 三项皆命中
- [ ] 无全量 `useTrace()` 订阅；`actions` / `days` / `snapshots` / `seen` / `visits` 均有长度上限
- [ ] 多标签：`BroadcastChannel` 生效，两标签内容差异符合 3.4 定义；关闭其一后另一个固化
- [ ] 自然日一律经 `localDay()` 取得，`src/` 中不出现 `toISOString().slice(0, 10)`
- [ ] 判定不散落：`src/components/**` 与 `src/app/**` 中不出现 `tierOf(`、`SEEN_GATE_MS`、`round >`、`dn >`（这些只允许在 `lib/resolve/` 与 `lib/reader.ts` 内）
- [ ] 代码与构建产物中不出现 L0 数值系统术语（清单见下，须逐条窄化）
- [ ] 移动端（iOS Safari + Android Chrome）可完整走通"阅读 → 复制 → 隔天回访"路径，无页面卡死、无 OOM
- [ ] Chrome / Firefox / Safari 三端一致（`copy` 事件与 `Selection` API 行为差异需实测）

**术语自查分两条窄清单，各自可证伪。** 宽清单（如 `grep -i "budget\|channel\|pruning\|finalize\|observation"`）必然命中 `BroadcastChannel`、`IntersectionObserver`、`finalize()`、Tailwind 的 `transition-*` 这类正当标识符；长期报假阳性的自查等于没有自查。

```bash
# (a) L0 数值系统的专有标识符：这些词只可能来自设定文档，代码里出现即为越界
grep -rniE "\b(anomalyLevel|observationBudget|channelScore|weightTier|pruning|consumeBudget|entityfication|驻留缓存|全覆盖区)\b" src/

# (b) 玩家可见文本里的禁用词：只在字符串字面量中查，不查标识符
grep -rnE "(观测强度|预算余量|权重|档位|已解锁|检测到您|异常等级)" src/
```

(a) 必须为空。(b) 命中的每一条人工判定是否为站内口吻所允许（规则 1 的站内文本会合法提到"变慢"）。`BroadcastChannel`、`IntersectionObserver`、`selectionchange` 等浏览器 API 名不在任何禁用清单内。

### 8.3 反指标（出现即判失败）

- 玩家能复述出"网站想让我做什么"
- 玩家认为这是"一个带恐怖皮肤的博客"（说明变化只发生在屏幕层）
- 玩家第一次就笃定"是网站在改我的东西"（说明变化太强、太快，缺少"我记错了"的缓冲）
- 任何特效痕迹（模糊、抖动、乱码、变红、闪烁）
- 出现进度、百分比、等级、成就、解锁提示
- 首页能看出异常

### 8.4 黄金测试（`resolve()` 的断言集，先于 UI 存在）

`resolve` 是纯函数，输入是 `WorldState`，不需要浏览器、不需要设备、不需要测试者。这组断言是本切片唯一的机器可证伪层——上面所有"感知类"标准都要 3 个真人、3 个自然日才能验，而这一层十秒跑完。**任何一条红了，不进入真人测试。**

```typescript
// __tests__/golden.test.ts
import type { ContentBlock } from '@/types';
import { resolve } from '@/lib/resolve/resolve';
import { ENTRIES, VERIFY_BLOCKS, RESERVED_NUMBERS } from '@/data/entries';
import { ROUND_MAX } from '@/lib/resolve/roundFor';

const W = (over = {}) => ({ round: 0, seenMs: 10_000, snapshot: undefined, ...over });
const canon = (b: ContentBlock) => b.text ?? '';

test('1. 首轮恒为规范版：任何块、任何停留时长，round = 0 都不许漂', () => {
  for (const e of ENTRIES) for (const b of e.blocks) {
    expect(resolve(b, W({ round: 0, seenMs: 600_000 })).text).toBe(canon(b));
  }
});

test('2. 未看过不漂：seenMs 低于门槛时，round >= 1 也返回规范版', () => {
  for (const e of ENTRIES) for (const b of e.blocks) {
    expect(resolve(b, W({ round: ROUND_MAX, seenMs: 0 })).text).toBe(canon(b));
    expect(resolve(b, W({ round: ROUND_MAX, seenMs: 1_499 })).text).toBe(canon(b));
  }
});

test('3. 门槛在数据里：minRound: 2 的块在 round = 1 仍为规范版', () => {
  for (const e of ENTRIES) for (const b of e.blocks) if ((b.minRound ?? 1) > 1) {
    expect(resolve(b, W({ round: b.minRound! - 1 })).text).toBe(canon(b));
  }
});

test('4. 只前进不回退：round 递增序列上，一旦漂过就永不返回规范版', () => {
  for (const e of ENTRIES) for (const b of e.blocks) if (b.driftable && b.variants?.length) {
    let drifted = false;
    for (let r = 0; r <= ROUND_MAX; r++) {
      const got = resolve(b, W({ round: r })).text;
      if (got !== canon(b)) drifted = true;
      else expect(drifted).toBe(false);        // 漂过之后又变回规范版 = 失败
    }
  }
});

test('5. 定稿即冻结：有快照的块在任何轮次都逐字等于快照，而非规范版', () => {
  for (const e of ENTRIES) for (const b of e.blocks) {
    const fossil = '【当时所见的一版】';
    const out = resolve(b, W({ round: ROUND_MAX, snapshot: fossil }));
    expect(out.text).toBe(fossil);
    expect(out.tier).toBe('high');
  }
});

test('6. 对照物独占值：任何变体文本都不得让 RESERVED_NUMBERS 作为独立数值出现', () => {
  // 必须做"独立数值"匹配而不是子串匹配：`repair` 的 round 1 是 03:26:15，
  // 朴素的 text.includes('15') 会因为时间串里恰好有 15 而误报，
  // 一条长期误报的检查等于没有检查（同 §8.2 术语自查的教训）。
  const hit = (text: string, n: string) =>
    new RegExp(`(?<![\\d:.])${n.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')}(?![\\d:.])`).test(text);
  for (const e of ENTRIES) for (const b of e.blocks) for (const v of b.variants ?? []) {
    for (const n of RESERVED_NUMBERS) expect(hit(v.text, n)).toBe(false);
  }
});

test('6b. 独占表不空转：每一项都必须真的出现在对照物文书里', () => {
  const doc = Object.values(VERIFY_BLOCKS).map((b) => b.text ?? '').join('\n');
  for (const n of RESERVED_NUMBERS) expect(doc).toContain(n);
});
```

再加一条对照物页自身的断言，它不属于 `resolve` 但同样是机器可查的：

```typescript
test('7. 对照物与轮次无关：verify 文本只来自快照，不来自 variants', () => {
  for (const b of Object.values(VERIFY_BLOCKS)) {
    expect(b.variants ?? []).toHaveLength(0);
    expect(b.driftable ?? false).toBe(false);
  }
});
```

断言 1–7 打在 `resolve` 上，与真实时钟无关。依赖时钟的两条（本地自然日、轮次上界，`02 §4.5` 第 1、2 条）单独放一个文件，且**必须在跑该文件前把时区钉死**：在 `vitest.config.ts` 里设 `test: { env: { TZ: 'Asia/Shanghai' } }`，不要在测试代码里改 `process.env.TZ`（Node 读取时区的时机不保证，改不生效是静默的，一条永不失败的断言比没有断言更糟）。

```typescript
// __tests__/round.test.ts
import { roundFromDn, ROUND_MAX } from '@/lib/resolve/roundFor';
import { localDay } from '@/lib/traceStore';

test('8. 推进单位是本地自然日：同一天内无论几点访问，dn 恒为 1', () => {
  // UTC+8 的凌晨 00:12 与前一天 23:59 属于同一个本地日，却分属两个 UTC 日。
  // 这条断言专门杀 `toISOString().slice(0, 10)`：改成 UTC 日，集合立刻分裂成两个。
  const stamps = ['2026-03-13T23:59', '2026-03-14T00:12', '2026-03-14T08:30'];
  const days = new Set(stamps.map((s) => localDay(new Date(s))));
  expect(days.size).toBe(2);                   // 13 日一次、14 日两次
  expect(roundFromDn(days.size)).toBe(1);      // 只推进一轮，不因同日内多次访问而加速
});

test('9. 轮次有上界：回访再多也不越过 ROUND_MAX', () => {
  expect(roundFromDn(1)).toBe(0);
  expect(roundFromDn(2)).toBe(1);
  for (let dn = 1; dn <= 60; dn++) {
    expect(roundFromDn(dn)).toBeLessThanOrEqual(ROUND_MAX);
  }
  expect(roundFromDn(ROUND_MAX + 1)).toBe(ROUND_MAX);
  expect(roundFromDn(ROUND_MAX + 9)).toBe(ROUND_MAX);   // 第 5 天起不再产生新变化（02 §4.5 第 2 条）
});
```

`02 §4.5` 第 3 条（回访不锁定、不定稿）不由轮次断言覆盖，它由写入路径的唯一性保证：`snapshots` 只有 `snapshot()` 一个写入者，而 `snapshot()` 只在精确选中与复制里被调用（§3.4）。断言 5 验的是这个动作的**结果**，"没有别的入口"靠 §8.2 的标识符自查兜底（人工项）。

第 6 条检查的不是代码而是**数据之间的事实关系**：`infra` 变体写没写 15，逐行校对看不出来（每句单独读都对），只有把 §4.5 的数字当成约束集去比对才会红。

各条对应的缺陷：1 杀"`round` 未参与判定"，2 杀"划过即漂"，3 杀"门槛写死在组件里、数据改了组件不知道"，4 杀"某天悄悄退回规范版"。

### 8.5 fixture 注入（`?fixture=day3`，仅开发）

真人测试要 3 个自然日，代码评审不能等；同时评审者需要看见"第 3 天世界长什么样"，而这必须与玩家第 3 天真实看到的是同一份。因此注入的**只能是 `WorldState` 的输入，绝不能是判定结果**。

```typescript
// lib/dev/fixtures.ts
import type { WorldState } from '@/lib/resolve/resolve';

export const FIXTURES: Record<string, Partial<WorldState>> = {
  day1: { round: 0, seenMs: 10_000 },
  day2: { round: 1, seenMs: 10_000 },
  day3: { round: 2, seenMs: 10_000 },
  day4: { round: 3, seenMs: 10_000 },
  skim: { round: 3, seenMs: 200 },          // 泛读：高档轮次 + 低档停留
  fossil: { round: 3, snapshot: '【快照】' },
};

export function fixtureFromUrl(): Partial<WorldState> {
  if (process.env.NODE_ENV === 'production') return {};       // 生产环境第一道闸
  const k = new URLSearchParams(window.location.search).get('fixture');
  return (k && FIXTURES[k]) || {};
}
```

`useResolved` 里合并的顺序是硬要求——fixture 覆盖输入，`resolve` 仍然是唯一判定者：

```typescript
return resolve(block, { round, seenMs, snapshot, ...fixtureFromUrl() });
```

三条约束：

1. **不得为演示新增第二条渲染路径。** fixture 一旦走 `DemoVariantSpan`，评审看到的就不再是玩家会看到的，本节意义消失。
2. **构建产物里必须查得到空。** `next build` 后 `grep -r "day3\|fixtures" out/` 应为空。仅靠 `process.env.NODE_ENV` 的运行时判断不够——`?fixture=` 这个字符串仍可能残留在客户端 bundle 里，两条一起才算过关。
3. fixture 只能覆盖 `round` / `seenMs` / `snapshot`。**不许造 `visits`、不许直接写 `localStorage`**——那是第二个真相源，与 §3.2 禁止"把轮次写回 store"同理。

推进条件因此仍然只有一条实现路径；fixture 提供的是**观测的便利**，不是世界的后门。

## 九、注意事项

1. **不要过度设计。** 切片只验证第七、八节那一条回路。判据是"`04 §二` 的主映射表里有没有它"，不是"`04 §十` 有没有明令禁止"——`04 §十` 只是已知未决项（非穷尽），未进映射表的概念（全覆盖区、驻留缓存、高权值观测单位实体化）本期一律不实现。
2. **先让基础 Wiki 完美运转，再加变化。** 一个不像真网站的壳，会让所有变化提前归因为"游戏设计"。
3. **克制优于聪明。** 宁可让玩家怀疑自己看错，也不要让他觉得"这个网站在搞鬼"。
4. **不实现的东西不要留字段。** 只留 `variants`、`driftable`、`minRound`，三者在 §3.3.1 都有真实读者；不预留 `anomalyLevel` 这类字段——预留一个语义错误的字段，一定会有人开始往里写数值系统。
